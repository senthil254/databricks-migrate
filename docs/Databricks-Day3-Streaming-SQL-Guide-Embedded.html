1. Key words

  • Volume: a governed folder for files.
  • Streaming table: a table that loads only new data.
  • Materialized view: a saved query result, kept up to date.
  • Bronze: raw copy of the files.
  • Silver: cleaned data.
  • Gold: business totals.
  • STREAM: read only what is new.
  • Checkpoint: saved progress. Databricks manages it here.

2. The whole flow

  • Files land in the volume.
  • Bronze copies them.
  • Silver cleans them.
  • Gold adds them up.

3. Attach the right compute

  • Use the Serverless Starter Warehouse.
  • Serverless notebook compute fails.
  • Classic clusters fail.

8. Stream CSV into bronze

About this code
What
Creates orders_bronze from the CSV folder.
Why
Bronze is a raw copy, with the source file.
When
First run loads all. Later runs load new files.
Where
Streaming table in day3_streaming.demo.
How, line by line
  • CREATE OR REFRESH: keeps what is loaded.
  • *: all CSV columns.
  • _metadata.file_name: source file.
  • current_timestamp(): load time.
  • STREAM read_files: new files only.
  • schemaEvolutionMode: new columns are added.
CREATE OR REFRESH STREAMING TABLE day3_streaming.demo.orders_bronze   -- create once, refresh after
COMMENT 'Streaming ingest of CSV order files from the volume'
AS SELECT
     *,                                        -- every CSV column
     _metadata.file_name AS source_file,       -- which file the row came from
     current_timestamp()  AS ingested_at       -- when it was loaded
   FROM STREAM read_files(                     -- STREAM = only new files
     '/Volumes/day3_streaming/demo/raw_files/orders',
     format               => 'csv',
     header               => true,
     schemaEvolutionMode  => 'addNewColumns'); -- accept new columns
OutputThe operation was successfully executed.

9. Stream Parquet into bronze

About this code
What
Creates events_bronze from Parquet files.
Why
Same pattern, another format.
When
With the CSV table.
Where
Streaming table.
How, line by line
  • Columns listed to cast event_time.
  • CAST(... AS TIMESTAMP): avoids the timestampNtz error.
  • format => 'parquet': schema from the file.
CREATE OR REFRESH STREAMING TABLE day3_streaming.demo.events_bronze
COMMENT 'Streaming ingest of Parquet sensor events from the volume'
AS SELECT
     event_id, device_id, region,                  -- identifiers
     temperature, humidity, battery_pct,           -- readings
     CAST(event_time AS TIMESTAMP) AS event_time,  -- avoids timestampNtz error
     _metadata.file_name AS source_file,           -- source file
     current_timestamp()  AS ingested_at           -- load time
   FROM STREAM read_files(
     '/Volumes/day3_streaming/demo/raw_files/events',
     format => 'parquet');
OutputThe operation was successfully executed.
Two real Parquet errors
  • PARQUET_TYPE_ILLEGAL … NANOS: file uses nanoseconds. Write microseconds.
  • timestampNtz feature error: cast to TIMESTAMP.

10. Stream bronze into silver

About this code
What
Builds orders_silver from bronze.
Why
Clean data, bronze untouched.
When
After bronze.
Where
Streaming table.
How, line by line
  • FROM STREAM table: new rows only.
  • order_total: new column.
  • WHERE: drops cancelled orders.
CREATE OR REFRESH STREAMING TABLE day3_streaming.demo.orders_silver
COMMENT 'Streaming write: cleansed orders derived from orders_bronze'
AS SELECT
     order_id, customer_id, product, region,
     quantity, unit_price,
     ROUND(quantity * unit_price, 2) AS order_total,   -- value of the order
     status, ordered_at, source_file
   FROM STREAM day3_streaming.demo.orders_bronze        -- new bronze rows only
   WHERE status <> 'cancelled';                         -- drop cancelled
OutputThe operation was successfully executed. silver rows: 1,804 (cancelled orders removed)

11. Gold materialized view

About this code
What
Revenue by region and product.
Why
Totals need a materialized view.
When
After silver.
Where
Materialized view.
How, line by line
  • count(*): orders.
  • sum(order_total): revenue.
  • avg(order_total): average order.
  • GROUP BY: one row per region + product.
CREATE OR REPLACE MATERIALIZED VIEW day3_streaming.demo.orders_gold
COMMENT 'Gold: revenue by region and product'
AS SELECT
     region, product,                          -- one row per group
     count(*)                    AS order_count,
     ROUND(sum(order_total), 2)  AS revenue,
     ROUND(avg(order_total), 2)  AS avg_order
   FROM day3_streaming.demo.orders_silver
   GROUP BY region, product
   ORDER BY revenue DESC;

SELECT * FROM day3_streaming.demo.orders_gold LIMIT 10;

13. Common problems

ST_NOT_ENABLED_ON_SERVERLESS_GENERIC_COMPUTEAttach the SQL warehouse.
PARQUET_TYPE_ILLEGAL … NANOSWrite microsecond timestamps.
timestampNtz errorCAST(col AS TIMESTAMP).
New files ignoredUse a new file name.
Everything reprocessedUse CREATE OR REFRESH, not REPLACE.
Aggregate rejectedUse a materialized view.
CREATE CATALOG deniedAsk an admin, or use an existing catalog.

14. Cost and cleanup

  • A refresh bills only while it runs.
  • The warehouse auto-stops after 10 idle minutes.
  • Stopping does not delete data.
  • Cleanup is text only in the notebook.
DROP MATERIALIZED VIEW IF EXISTS day3_streaming.demo.orders_gold;  -- gold first
DROP TABLE IF EXISTS day3_streaming.demo.orders_silver;
DROP TABLE IF EXISTS day3_streaming.demo.orders_bronze;
DROP TABLE IF EXISTS day3_streaming.demo.events_bronze;
DROP VOLUME IF EXISTS day3_streaming.demo.raw_files;               -- deletes the files
DROP SCHEMA IF EXISTS day3_streaming.demo;
DROP CATALOG IF EXISTS day3_streaming;

  • Bronze = raw · Silver = clean · Gold = totals.
  • CREATE OR REFRESH keeps progress.
  • DESCRIBE HISTORY proves it.
